# Product UI Quality Gates

日期：2026-08-29
用途：作为 `agent-team-router` 的按需参考；用于 Product UI、配置台、管理台、列表页、审核页、监控页或高频操作型界面的设计和交付自检。

只有任务命中 Product UI / UX / 管理台 / 操作型界面时读取。普通架构、研究、工具实现或路径明确的小修不加载。

## 先定义用户任务

`UX_Product_Design_AGENT` 不能从组件或视觉装饰开始。动手前先写清：用户此刻要完成什么、必须看到什么、会作出什么决定、动作何时真正生效。

- 先判断界面类型、任务密度和主要操作，再选择布局；配置台优先紧凑、可扫、可比较，不用松散大卡片承载少量字段。
- 先冻结信息层级：主任务与当前值为一级，状态与结果为二级，来源、路径、ID、实现细节和调试信息为三级或隐藏。未分层前不排版。
- 配置面板只表达用户能控制的业务语义、当前选择和必要结果；模型窗口、内部公式、provider、缓存、保护上限等运行时实现默认不披露。
- 一段说明只有在帮助选择、正确填写、理解影响或解除错误时才保留；只是复述标题、解释实现或证明系统“考虑过”的文字直接删除。
- 用户连续指出“看不懂、太技术、换行丑、信息多余”时，停止局部换词，回到任务、层级、控件语义和状态流重新设计。

## 布局与视觉层级

- 同一决策的标题、选项和从属输入必须形成一个紧凑视觉组；不要让说明、单位或错误漂在卡片远端。
- 普通配置不额外嵌套多层卡片、渐变、阴影和装饰标题；视觉容器只用于表达真实分组、层级或状态。
- 状态靠近对象身份，字段反馈靠近字段，动作固定在所属层级；页面级、对象级、步骤级、行级和字段级动作不得混放。
- 路径、ID、更新时间、来源等技术元信息降级为二级文本、窄列或 tooltip；空描述、重复标签、机械 slug 和内部枚举不得撑大界面。
- 控件、单位和直接修饰语尽量保持同一行；避免把一句工程说明单独换成孤立尾行。中文管理台在真实容器宽度下必须检查自然换行、行长和左右缩进，不能只看宽屏理想画布。
- 颜色只表达语义：普通选中和导航使用低饱和浅底、边框或文本层级；强色只用于主动作、危险、失败或强注意状态。

## 控件语义

先按行为选控件，不能因为“只有两个选项”就默认使用切换器。

| 控件 | 适用语义 | 不适用 |
| --- | --- | --- |
| `Radio group` | 短列表中的互斥表单选择；需要保存、带说明或有从属字段 | 页面导航、即时视图切换 |
| `Segmented control` | 同一维度、紧密相关、选择后立即应用、没有从属输入 | 显式保存表单、会展开输入的配置策略 |
| `Tabs` | 切换内容上下文或步骤页，保持对象和动作位置稳定 | 直接写值、保存、删除或发布 |
| `Switch` | 一个布尔状态，切换即产生明确结果 | 两种复杂策略、需要后续输入的选择 |
| `Select / Combobox` | 选项较多、需要搜索或空间受限的单选 | 2-5 个需要比较说明的短选项 |

- 原生语义必须成立：互斥表单用 `fieldset/legend` 或等价可访问分组；标签可点击；焦点、hover、selected、disabled 和错误状态可辨认且不只依赖颜色。
- 同一表单不能混用自动保存与显式保存。显式保存表单中的选项只更新草稿，最终由统一保存动作提交；即时控件只有在用户预期立刻看到结果时才自动保存。

## 渐进披露与“默认 / 自定义”

- 默认项预选；自定义项放在组末尾，选中后只在其下方就近展开真正需要填写的控件，不展开解释段落。
- 进入自定义模式不能静默制造或持久化猜测值。输入为空时保持未覆盖；用户输入有效值后才形成 override；切回默认时清除 override。
- 从属控件的标签要能独立说明需要填写什么；单位贴近数值，placeholder 只给格式示例，不能代替标签或默认值。
- 条件区域出现后，键盘和阅读顺序应自然进入该字段，不应让用户误以为跳到下一问题；复杂 radio 组或多个条件区必须做键盘和读屏顺序检查。
- 自定义值被内部边界约束时，默认不展示公式或保护实现；只有用户必须据此修正输入时，才给出具体、可行动的字段错误。

## 文案与数值

- 标题与标签使用用户动作或结果，例如“何时压缩”“指定 Token 数”；避免“策略、机制、阈值、兜底、安全上限”等只有实现者熟悉的抽象名词，除非目标用户领域明确需要。
- 先说效果，再说条件；能用选项本身表达的内容不再加说明。推荐态写在选项标签内，不另起一行重复“推荐”。
- 说明文字使用一句完整短句；不把公式、内部 min/max、配置优先级或未来架构放进 UI。确需技术细节时进入帮助、tooltip 或文档。
- 数字采用一致单位、步长、范围和对齐；用户输入单位与持久化单位不同，界面必须稳定转换且不在切换模式时擅自改值。
- 错误指出“哪里不对 + 如何修正”，保留用户输入；不要用成功提示、warning 或长解释长期占据正常表单。

## 列表、筛选与监控

- 主列表负责浏览、比较和定位；筛选负责收窄集合；详情区查看单项细节；批量选择表达选择状态和例外。一个信息由主列表稳定承载后，侧栏不再重复铺一份。
- 筛选维度面向用户目标和可扩展数量级。来源、能力、状态和调用模式各司其职，不把 provider 内部命名或同步/异步实现混成用户分类。
- 同一维度可能超过 6 个选项时，顶层只保留稳定大类，具体对象用下拉、搜索、分组或二级导航；同类对象超过 6 个时优先表格、紧凑列表或折叠分组。
- 工具、资源、服务优先显示用户可理解的能力标签；内部 slug、provider 前缀和实现形态只能作为二级信息、tooltip 或调试字段。
- 监控首屏固定服务“筛选范围、判断异常、比较指标”三件事；异常只在一个稳定区域表达，指标按可比较行列组织，不用 Hero、方法论说明或供应商实现挤占首屏。
- 监控状态区分数据可用性与指标健康度；有数据不等于健康，缺数据不能写“零异常”，只有窗口聚合值时不得伪造趋势。
- 指标达到 6 项时使用比较表、紧凑列表或按实体折叠；数值统一对齐和单位，异常优先。需要比较的同单位序列共享时间轴，不重复成独立大卡和小图。

## 多步骤与反馈

- 多步骤配置、接入、发布或审核使用步骤页 / tab 导航；点击步骤只切换上下文，不暗含保存、发布、删除或刷新。
- 每个步骤页必须承载不同输入、产物和下一步；对象身份、导航、摘要和主要动作位置保持稳定，只替换当前内容区。
- loading、空、错误、disabled、成功与重试状态必须服务任务流；反馈可关闭或自动消失，不长期挤占主内容。
- 搜索、筛选、刷新、同步和重试等轻量动作贴近所属对象，视觉重量低于主信息；高风险动作有明确影响范围和确认。

## 真实页面验收

UI 改动不能只靠 DOM、测试或代码审查宣称完成。主 Agent 必须在真实页面、真实容器宽度和真实数据下检查：

1. 默认态、自定义/展开态、无效输入、disabled 与错误态。
2. 密度、对齐、层级、可扫性、自然换行、单位位置和内容高度变化。
3. 鼠标与键盘操作、焦点顺序、hover/selected 可见性和标签点击区域。
4. 是否存在大面积空白、左右散点、按钮漂移、信息重复、孤立尾行或内部实现泄漏。
5. 监控页额外检查有数据与无数据/不可判断两种状态；首屏同时看得到筛选、异常结论和主要指标。

发现上述问题先迭代页面，再跑截图/交互复验。用户指出设计质量不佳时，最多连续进行 3 轮规则修正；每轮说明修正点、预期改善和仍未解决的问题。第 3 轮后停止扩写规则，直接做产品决策和 UI 实现。
